  <files>scripts/dispatch/approval-gate.sh</files>
  <action>
Create scripts/dispatch/approval-gate.sh with the following functions:

**check_existing_approval(workspace_id, task_description)**
- Look for approved cross_workspace approval matching this workspace
- Search in .worker/approvals/approved/*.json for matching workspace
- Return 0 if valid approval exists (proceed), 1 if not found
- Used to allow re-runs after approval granted

**check_approval_requirement(workspace_id, task_description, trust_level)**
- If trust_level < 3: return 0 immediately (no approval needed)
- Check for existing approval: if approved, return 0
- If not approved, create new approval request:

Create context JSON:
```bash
context_json=$(jq -nc \
    --arg workspace "$workspace_id" \
    --arg task "$task_description" \
    --arg level "$trust_level" \
    '{
        workspace: $workspace,
        task: $task,
        trust_level: ($level | tonumber),
        operation_type: "cross_workspace_dispatch"
    }')
```

Source approval-workflow.sh and call:
```bash
local approval_id
approval_id=$(create_approval_request "cross_workspace" "orchestrator" "$context_json")
```

Print user instructions to stderr:
- "Cross-workspace operation requires CEO approval (Trust Level $trust_level)"
- "Approval request created: $approval_id"
- "Dispatched to CEO inbox for review."
- "To approve: Review in inbox and respond with 'approve $approval_id'"
- "To deny: Respond with 'deny $approval_id'"
- "To defer: Respond with 'defer' (creates GitHub issue)"
- "Re-run this command after approval to continue."

Return 1 to block dispatch (exit-and-resume pattern)

**_get_approval_workflow_path()**
- Returns absolute path to approval-workflow.sh
- Uses REPO_ROOT or fallback discovery

Script conventions:
- Use _APPROVAL_GATE_SCRIPT_DIR pattern
