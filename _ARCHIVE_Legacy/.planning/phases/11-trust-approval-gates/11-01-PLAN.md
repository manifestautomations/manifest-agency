<task type="auto">
  <name>Task 1: Create trust validation script</name>
  <files>scripts/dispatch/trust-validation.sh</files>
  <action>
Create scripts/dispatch/trust-validation.sh with the following functions:

**get_current_trust_level(ledger_path)**
- Parse Current Level from trust ledger markdown table
- Table format: `| **Current Level** | N (Trust Name) |`
- Use: `grep -i "Current Level" | awk -F'|' '{print $3}' | tr -d ' ' | grep -oE '^[0-4]'`
- Default to 0 if ledger missing or parse fails (most restrictive)
- Log parse failures to stderr for diagnostics

**get_trust_ceiling(ledger_path)**
- Parse Trust Ceiling from trust ledger markdown table
- Table format: `| **Trust Ceiling** | N (inherited from parent) |`
- Use same grep/awk pattern as above
- Default to 4 if not found (max ceiling)

**validate_trust_ceiling(workspace_path, parent_ceiling)**
- Get child's current trust level and recorded ceiling from workspace's trust ledger
- Validation 1: Child ceiling must not exceed parent ceiling (config mismatch)
- Validation 2: Child current level must not exceed parent ceiling (constraint violation)
- On violation: call generate_improvement_analysis and return 1
- On pass: return 0

**generate_improvement_analysis(workspace_path, child_level, parent_ceiling)**
- Extract workspace_name from basename
- Compare .claude/ directories between parent and child (agents, skills counts)
- Print analysis to stderr showing what child has that parent doesn't
- Call _create_improvement_task to create GitHub issue (best effort)

**_create_improvement_task(workspace_name, child_level, parent_ceiling)**
- Check for existing improvement task first: `gh issue list --label "trust-system" --search "$workspace_name"`
- If exists, skip to prevent duplicate issues
- If gh CLI unavailable, skip silently
- Create issue with title "[Improvement] Analyze why $workspace_name outperformed parent"
- Body includes: context, analysis steps, actionable diff commands, recommendation
- Labels: enhancement, trust-system, pending-review

Script conventions:
- Use _TRUST_SCRIPT_DIR pattern to avoid variable overwrites when sourced
- Include re-source guard at top
- Export all public functions (get_*, validate_*)
- Use set -euo pipefail only in direct execution block
