  <action>
Create dispatch script that orchestrator uses to spawn Claude workers.

Command-line interface:
```bash
./dispatch.sh --issue 42              # Dispatch single issue
./dispatch.sh --issues "42 43 44"     # Dispatch multiple (parallel)
./dispatch.sh --all-ready             # Dispatch all ready issues
./dispatch.sh --with-dependencies     # Full dependency-ordered dispatch
./dispatch.sh --max-concurrent 3      # Limit parallel workers (default: 3)
./dispatch.sh --dry-run               # Show what would be dispatched
```

Functions to implement:

1. `dispatch_single()` - Dispatch one worker
   - Invoke: `scripts/worker/execute.sh --issue N`
   - Run in background for parallel dispatch
   - Track PID for job control
   - Log dispatch event

2. `dispatch_parallel()` - Dispatch multiple with limit
   - Use bash job control (wait -n for bash 4.3+)
   - Track active workers in associative array
   - Wait when at max_concurrent limit
   - Clean up completed workers

3. `dispatch_with_dependencies()` - Full dependency-aware dispatch
   - Source graph.sh for dependency functions
   - Get topological order from get_execution_order
   - Dispatch in waves based on dependency graph
   - Wait for each wave before next

4. `on_worker_complete()` - Handle worker completion
   - Check exit code
   - On success: proceed to dependents
   - On failure: call detect_cascade, label blocked issues

Implementation from RESEARCH.md Pattern 5:
```bash
# Track running workers
declare -A worker_pids

# Wait if at limit
while [ ${#worker_pids[@]} -ge $max_concurrent ]; do
  wait -n
  # Clean up completed
done

# Dispatch in background
scripts/worker/execute.sh --issue "$issue" &
worker_pids[$issue]=$!
```

Windows/MINGW64 considerations:
- wait -n available in bash 4.3+ (verify with bash --version)
- Background jobs work normally
- Signal handling via trap

Include logging for observability (reuse patterns from worker).
