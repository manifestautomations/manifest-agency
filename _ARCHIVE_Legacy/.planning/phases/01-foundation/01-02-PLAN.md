  <name>Task 1: Create agent manifest JSON Schema</name>
  <files>schemas/agent-manifest.schema.json</files>
  <action>
Create `schemas/` directory and define the agent manifest schema.

The schema must support (from CONTEXT.md decisions):
- Universal base: name, version, author, description, dependencies, resource requirements, execution context, routing hints
- Constraints as allowlist AND blocklist with sensible defaults
- Optional triggers (agents can be invoked directly OR auto-triggered)
- Provider-specific extensions: Claude (skills, toolSchemas), Gemini (functionDeclarations, grounding)

Schema structure (JSON Schema draft-07 for wide compatibility):

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "$id": "https://manifest-automations.dev/schema/agent-manifest/v1.0.0",
  "title": "Agent Manifest",
  "description": "Declarative definition of an AI agent for Manifest Automations",
  "type": "object",
  "required": ["name", "version", "tools"],
  "properties": {
    "name": {
      "type": "string",
      "pattern": "^[a-z0-9][a-z0-9-]*[a-z0-9]$",
      "description": "Agent identifier in kebab-case (e.g., code-reviewer)",
      "minLength": 3,
      "maxLength": 50
    },
    "version": {
      "type": "string",
      "pattern": "^\\d+\\.\\d+\\.\\d+$",
      "description": "Semantic version (e.g., 1.0.0)"
    },
    "author": {
      "type": "string",
      "description": "Author or team responsible for this agent"
    },
    "description": {
      "type": "string",
      "description": "What this agent does",
      "maxLength": 500
    },
    "tools": {
      "type": "array",
      "items": { "type": "string" },
      "minItems": 1,
      "description": "Tools this agent can use (e.g., read_file, write_file, run_bash)"
    },
    "dependencies": {
      "type": "array",
      "items": { "type": "string" },
      "description": "Other agents this agent depends on"
    },
    "resources": {
      "type": "object",
      "properties": {
        "memory": { "type": "string", "description": "Memory requirement (e.g., 4GB)" },
        "timeout": { "type": "integer", "description": "Max execution time in seconds" }
      },
      "description": "Resource requirements for execution"
    },
    "execution": {
      "type": "object",
      "properties": {
        "workdir": { "type": "string", "description": "Working directory context" },
        "isolated": { "type": "boolean", "description": "Run in isolated worktree" }
      },
      "description": "Execution context settings"
    },
    "routing": {
      "type": "object",
      "properties": {
        "priority": { "type": "integer", "minimum": 0, "maximum": 100 },
        "tags": { "type": "array", "items": { "type": "string" } }
      },
      "description": "Hints for orchestrator routing"
    },
    "constraints": {
      "type": "object",
      "properties": {
        "allow": {
          "type": "array",
          "items": { "type": "string" },
          "description": "Glob patterns for allowed file access (e.g., src/**)"
        },
        "deny": {
          "type": "array",
          "items": { "type": "string" },
          "description": "Glob patterns for denied file access (e.g., **/.env)"
        }
      },
      "description": "File access constraints (allowlist + blocklist)"
    },
    "triggers": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "type": { "type": "string", "enum": ["workflow", "skill", "event", "schedule"] },
          "name": { "type": "string" },
          "config": { "type": "object" }
        },
        "required": ["type", "name"]
      },
      "description": "Optional triggers for auto-invocation"
    },
    "providers": {
      "type": "object",
      "properties": {
        "claude": {
          "type": "object",
          "properties": {
            "skills": { "type": "array", "items": { "type": "string" } },
            "toolSchemas": { "type": "array", "items": { "type": "string" } }
          },
          "description": "Claude-specific extensions"
        },
        "gemini": {
          "type": "object",
          "properties": {
            "functionDeclarations": { "type": "array", "items": { "type": "string" } },
            "grounding": { "type": "boolean" }
          },
          "description": "Gemini-specific extensions"
        }
      },
      "description": "Provider-specific extensions"
    }
  },
  "additionalProperties": false
}
```

Ensure the JSON is valid and well-formatted. The schema is intentionally strict (additionalProperties: false) to catch typos.

Create two example agents that demonstrate different aspects of the schema:

**1. code-reviewer.yaml** (minimal + Claude-specific):
```yaml
# yaml-language-server: $schema=../../schemas/agent-manifest.schema.json
name: code-reviewer
version: 1.0.0
author: Manifest Automations
description: Reviews code for style, security, and best practices

tools:
  - read_file
  - run_bash

constraints:
  allow:
    - "src/**"
    - "tests/**"
    - "*.md"
  deny:
    - "**/.env"
    - "**/credentials.json"
    - "**/secrets/**"

triggers:
  - type: workflow
    name: pr-review
  - type: skill
    name: quick-audit

providers:
  claude:
    skills:
      - code-review
    toolSchemas:
      - mcp__linter__*
```

**2. backend-developer.yaml** (full-featured):
```yaml
# yaml-language-server: $schema=../../schemas/agent-manifest.schema.json
name: backend-developer
version: 1.0.0
author: Manifest Automations
description: Implements backend services, APIs, and database schemas

tools:
  - read_file
  - write_file
  - run_bash
  - glob
  - grep

dependencies:
  - code-reviewer

resources:
  memory: 8GB
  timeout: 3600

execution:
  workdir: "."
  isolated: true

routing:
  priority: 50
  tags:
    - backend
    - api
    - database

constraints:
  allow:
    - "src/**"
    - "prisma/**"
    - "tests/**"
    - "*.json"
    - "*.yaml"
  deny:
    - "**/.env*"
    - "**/credentials*"
    - "frontend/**"

providers:
  claude:
    skills:
      - backend-service
      - database-migration
    toolSchemas:
      - mcp__prisma__*
      - mcp__docker__*
  gemini:
    functionDeclarations:
      - create_api_endpoint
      - modify_schema
    grounding: true
```

These examples demonstrate:
- Schema reference for IDE support
- Minimal vs comprehensive configurations
- Constraints with both allow and deny lists
- Provider-specific extensions for both Claude and Gemini
- Dependencies between agents
- Resource and execution settings

# Agent Manifest Templates

Templates for creating new agent definitions.

## Quick Start

1. Copy `base.yaml` to `.claude/agents/<your-agent-name>.yaml`
2. Update the `name`, `version`, `author`, and `description`
3. Define the `tools` your agent needs
4. Set appropriate `constraints` (allow/deny patterns)
5. Add optional sections as needed

## Validation

Agent manifests are validated against `schemas/agent-manifest.schema.json`.

IDE Support: The `yaml-language-server` directive enables autocomplete and validation in VSCode with the YAML extension.

## Required Fields

- `name`: kebab-case identifier (3-50 chars)
- `version`: semantic version (e.g., 1.0.0)
- `tools`: array of tool names (at least one)

## Examples

See `.claude/agents/` for working examples:
- `code-reviewer.yaml` - Minimal agent with Claude extensions
- `backend-developer.yaml` - Full-featured agent with all options

## Schema Reference

Full schema documentation: `schemas/agent-manifest.schema.json`
