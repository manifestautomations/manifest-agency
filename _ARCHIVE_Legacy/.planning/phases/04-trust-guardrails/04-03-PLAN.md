<task type="auto">
  <name>Task 2: Create validator.sh library</name>
  <files>.claude/skills/worker/lib/validator.sh</files>
  <action>
Create validator.sh with comprehensive validation functions:

**Core functions:**

1. `load_guardrail_rules(agent)` - Load hierarchical config
   - Merge: hardcoded safety floor -> agency config -> project config -> agent manifest
   - Use yq to parse YAML, jq to merge
   - Return merged JSON rules
   - Cache result if performance needed (optional)

2. `validate_command(agent, trust_level, command)` - Validate command
   - Load rules via load_guardrail_rules
   - Check safety floor patterns first (always block, never override)
   - Check destructive patterns with severity
   - **Trust level resolution:** Accept trust_level as parameter (caller provides from:
     1. Worker config: `.worker/config.json` -> `guardrails.default_trust_level`
     2. Agent manifest: `.claude/agents/{agent}.yaml` -> `trust_level` field
     3. Runtime override: `--trust-level` flag passed to worker)
   - Determine action based on trust level + severity:
     - Return JSON: `{action: "allow|block|confirm", severity, reason, alternatives[]}`
   - Use command_matches_pattern for regex matching

3. `command_matches_pattern(command, pattern)` - Pattern matching
   - Normalize command (collapse whitespace)
   - Convert glob pattern to regex with security constraints
   - Use word boundaries for anchor
   - Return true/false

4. `validate_scope(agent, file_path, operation)` - Validate file access
   - Load agent manifest constraints (allow/deny patterns)
   - Resolve file path to canonical form (realpath -m)
   - Check deny list first (deny always wins)
   - Check allow list
   - Default: deny if no match
   - Return JSON: `{allowed: true|false, reason, matched_pattern, alternatives[]}`

5. `path_matches_pattern(path, pattern)` - Secure path matching
   - Use require_literal_separator (/ not matched by *)
   - Use require_literal_leading_dot (. not matched by *)
   - Convert glob to regex with these constraints

6. `record_violation(agent, command, reason, severity)` - Record violation
   - Calculate points based on severity (critical=100, high=15, medium=5, low=2)
   - Append to {agent}-violations.jsonl
   - Update trust-scores.json
   - Check thresholds (warning=20, probation=40, demotion=60)
   - Return status and new score

7. `apply_trust_decay(agent)` - Apply decay on clean action
   - Subtract 5 points from agent's score
   - Floor at 0
   - Update trust-scores.json
   - Log decay event

8. `get_trust_status(agent)` - Get current trust status
   - Read from trust-scores.json
   - Return JSON: `{score, status: "ok|warning|probation|demotion", last_violation}`

9. `handle_critical_violation(agent, command, pattern, issue)` - Handle critical violations
   - Create incident file with full context
   - Post to GitHub issue if available
   - Return incident_id
   - Exit with code 99 (do not call exit directly, let caller decide)

**Implementation notes:**
- Use yq for YAML parsing (installed in 04-01)
- Use jq for all JSON operations
- Patterns should be anchored and use word boundaries
- Safety floor patterns are hardcoded in the function, not read from YAML
- Alternatives should suggest safer commands when possible
