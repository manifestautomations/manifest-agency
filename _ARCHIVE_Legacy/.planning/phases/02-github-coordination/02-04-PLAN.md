  <action>
    Create `scripts/github/pr-create.sh` that:

    1. **Accepts parameters:**
       - `--issue <number>` (required) - The issue this PR closes
       - `--agent <name>` (required) - Agent identifier
       - `--worktree <path>` (optional) - Worktree path for metadata
       - `--start-time <epoch>` (optional) - Unix timestamp when work started (for duration calc)
       - `--title <title>` (optional) - Override auto-generated title
       - `--base <branch>` (optional) - Base branch, defaults to main
       - `--draft` (optional) - Create as draft PR

    2. **Gather metadata:**
       - Issue title: `gh issue view $ISSUE --json title -q '.title'`
       - Issue labels: Extract type (feature, bug, chore, etc.)
       - Commit count: `git rev-list --count HEAD ^$BASE`
       - Duration: Calculate from `--start-time` if provided
       - Trust level: From `$AGENT_TRUST_LEVEL` env var or default to 2
       - Model: From `$AGENT_MODEL` env var or default to "claude-sonnet-4.5"
       - Current branch: `git branch --show-current`

    3. **Generate PR title** (if not provided):
       Format: `<type>: <issue-title> (#<issue>)`
       - Extract type from issue labels (feature -> feat, bug -> fix, etc.)
       - Example: `feat: implement JWT refresh (#42)`

    4. **Build PR body** using template:
       - Load `templates/github/pr-body.md`
       - Replace placeholders: ISSUE_NUMBER, AGENT_NAME, WORKTREE_NAME, DURATION, MODEL_NAME, TRUST_LEVEL, COMMIT_COUNT
       - Prompt user to fill Summary and Changes sections OR accept via stdin

    5. **Create PR:**
       ```bash
       gh pr create \
         --title "$PR_TITLE" \
         --body "$PR_BODY" \
         --base "$BASE" \
         --head "$(git branch --show-current)" \
         ${DRAFT:+--draft}
       ```

    6. **Output:** PR URL and number

    Error handling:
    - Check we're in a git repo
    - Check we're not on main/master
    - Check issue exists
    - Check there are commits to push

<task type="auto">
  <name>Task 2: Create project query script</name>
  <files>scripts/github/project-query.sh</files>
  <action>
    Create `scripts/github/project-query.sh` that:

    1. **Accepts parameters:**
       - `--status <status>` (optional) - Filter by status (Ready, In Progress, etc.)
       - `--unclaimed` (optional) - Filter where Claimed By is empty
       - `--agent-type <type>` (optional) - Filter by agent type label
       - `--phase <number>` (optional) - Filter by phase
       - `--priority <P0|P1|P2|P3>` (optional) - Filter by priority
       - `--limit <number>` (optional) - Max items, default 50
       - `--format <json|table|list>` (optional) - Output format, default table
       - `--project <number>` (optional) - Project number, default 1

    2. **Query project items:**
       ```bash
       gh project item-list "$PROJECT" --owner "@me" --format json --limit "$LIMIT"
       ```

    3. **Filter with jq:**
       Build dynamic jq filter based on provided flags:
       ```bash
       JQ_FILTER='.items[]'

       if [ -n "$STATUS" ]; then
         JQ_FILTER="$JQ_FILTER | select(.status == \"$STATUS\")"
       fi

       if [ "$UNCLAIMED" = true ]; then
         JQ_FILTER="$JQ_FILTER | select(.fieldValueByName(\"Claimed By\").text == null or .fieldValueByName(\"Claimed By\").text == \"\")"
       fi
       # ... more filters
       ```

    4. **Format output:**
       - `json`: Raw JSON array
       - `table`: Formatted table with columns
       - `list`: Simple issue number and title per line

    5. **Common queries (document in --help):**
       ```bash
       # Find unclaimed Ready issues for any agent
       ./project-query.sh --status Ready --unclaimed

       # Find all in-progress work
       ./project-query.sh --status "In Progress"

       # Find blocked items
       ./project-query.sh --status Claimed  # then grep for blocked label

       # Find work by phase
       ./project-query.sh --phase 2
       ```

    Note on jq field access: The exact field access syntax depends on gh project item-list output format. May need to adjust based on actual output structure.
  </action>
  <verify>
    - `bash -n scripts/github/project-query.sh` passes
    - Script uses `gh project item-list`
    - Script pipes through jq for filtering
    - Script supports multiple filter flags
  </verify>

<task type="auto">
  <name>Task 3: Create generic field update script</name>
  <files>scripts/github/project-update-field.sh</files>
  <action>
    Create `scripts/github/project-update-field.sh` that:

    1. **Accepts parameters:**
       - `<issue-number>` (required, positional) - Issue to update
       - `--field <name>` (required) - Field name (Status, Priority, Complexity, etc.)
       - `--value <value>` (required) - New value
       - `--project <number>` (optional) - Project number, default 1

    2. **Load cached field definitions:**
       ```bash
       CACHE_FILE=".cache/github/project-fields.json"
       if [ ! -f "$CACHE_FILE" ]; then
         echo "Error: Run project-bootstrap.sh first"
         exit 1
       fi
       ```

    3. **Determine field type:**
       - Text fields: Claimed By
       - Single Select fields: Status, Priority, Complexity, Agent Type, Phase
       - Different mutation value format for each type

    4. **Get field ID and option ID (if single select):**
       ```bash
       FIELD_ID=$(jq -r ".data.organization.projectV2.fields.nodes[] | select(.name==\"$FIELD\") | .id" "$CACHE_FILE")

       # For single select, also get option ID
       if [ "$FIELD_TYPE" = "SingleSelect" ]; then
         OPTION_ID=$(jq -r ".data.organization.projectV2.fields.nodes[] | select(.name==\"$FIELD\") | .options[] | select(.name==\"$VALUE\") | .id" "$CACHE_FILE")
       fi
       ```

    5. **Get project item ID** for the issue

    6. **Execute update mutation:**
       ```bash
       # For text fields
       gh api graphql -f query='...' -f value="{ text: \"$VALUE\" }"

       # For single select fields
       gh api graphql -f query='...' -f value="{ singleSelectOptionId: \"$OPTION_ID\" }"
       ```

    7. **Use cases (document in --help):**
       ```bash
       # Update priority
       ./project-update-field.sh 42 --field Priority --value P1-high

       # Update complexity estimate
       ./project-update-field.sh 42 --field Complexity --value M

       # Update phase
       ./project-update-field.sh 42 --field Phase --value "phase:3"

       # Set agent type
       ./project-update-field.sh 42 --field "Agent Type" --value "agent:backend-developer"
       ```

    This script is the "Swiss army knife" for field updates - more specialized scripts (issue-claim, issue-update-status) can wrap it or use direct GraphQL for performance.
  </action>

    - Script uses updateProjectV2ItemFieldValue mutation
  </verify>
  <done>Generic field update script provides flexibility for any project field modification</done>
