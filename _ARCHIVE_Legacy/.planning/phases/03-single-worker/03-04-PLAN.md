Add this section after the "Script Reference" section (before "GitHub Actions Workflow"):

```markdown
## Worker Skill

The worker skill enables Claude to execute work from GitHub issues in isolated worktrees.

### Usage

```bash
# Execute work from an issue
claude --skill worker:execute --issue 42

# Override stale lock (after crash)
claude --skill worker:execute --issue 42 --force

# Check execution status
claude --skill worker:execute --issue 42 --status
```

### Workflow

1. **Lock acquisition** - Prevents concurrent execution on same issue
2. **Issue parsing** - Extracts Summary and Acceptance Criteria from issue body
3. **Plan generation** - Worker posts execution plan as issue comment
4. **Approval gate** - Human reviews plan, reacts with :+1: to approve
5. **Worktree creation** - Creates isolated `issue/{N}` branch
6. **Execution** - Worker implements the work
7. **PR creation** - Single commit, creates PR with agent metadata
8. **Cleanup** - Updates labels, releases lock

### State Machine

| Label | State | Description |
|-------|-------|-------------|
| `worker:planning` | Planning | Analyzing issue and generating plan |
| `worker:awaiting-approval` | Waiting | Plan posted, waiting for approval |
| `worker:executing` | Executing | Work in progress |
| `worker:complete` | Complete | PR created successfully |
| `worker:partial` | Interrupted | Execution interrupted, partial work exists |
| `worker:failed` | Failed | Error during execution |

### Issue Requirements

Issues must have structured format with these sections:

```markdown
## Summary
One-line description of the work

## Acceptance Criteria
- [ ] Criterion 1
- [ ] Criterion 2
```

### File Structure

```
.worker/
├── config.json           # Worker configuration
├── logs/                 # JSON event logs (gitignored)
│   └── issue-42-*.jsonl
└── locks/                # Lock files (gitignored)
    └── issue-42.lock

.claude/skills/worker/
├── execute.md            # Main worker skill
├── lib/
│   ├── logger.sh         # JSON logging functions
│   ├── lock.sh           # Lock management
│   └── parser.sh         # Issue body parsing
└── templates/
    ├── plan-comment.md
    ├── start-comment.md
    ├── complete-comment.md
    └── failure-comment.md
```

### Configuration

`.worker/config.json` settings:

| Setting | Default | Description |
|---------|---------|-------------|
| `command_timeout_seconds` | 600 | Max time per command (10 min) |
| `lock_staleness_threshold_seconds` | 1800 | When to consider lock stale (30 min) |
| `github_api_retry_attempts` | 3 | Retry count for GitHub API |
| `github_api_retry_delay_seconds` | 2 | Base delay between retries |

### Recovery

If worker crashes mid-execution:

1. Check status: `claude --skill worker:execute --issue 42 --status`
2. Options:
   - `--force` to override stale lock and restart
   - Check worktree at `../manifest-automations-issue-42/`
   - Review logs in `.worker/logs/`

### Example Session

```bash
# 1. Create issue with structured format
gh issue create --title "Add user profile endpoint" --body "$(cat <<EOF
## Summary
Create GET /api/users/:id endpoint returning user profile

## Acceptance Criteria
- [ ] Endpoint returns 200 with user object
- [ ] Endpoint returns 404 for unknown user
- [ ] Response includes id, name, email fields
EOF
)"

# 2. Start worker (posts plan, exits)
claude --skill worker:execute --issue 43

# 3. Review plan in GitHub issue, react with thumbs up

# 4. Re-run worker (executes after approval)
claude --skill worker:execute --issue 43

# 5. Worker creates PR, issue updated with completion comment
```
```

This documentation covers:
