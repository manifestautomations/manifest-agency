## End-to-End Flows

### Flow 1: CEO → Orchestrator → Worker → GitHub → Inbox

**Status:** COMPLETE

1. CEO inputs intent → Gemini orchestrate.md
2. intent.sh classifies request
3. decompose.sh + graph.sh build dependency graph
4. dispatch.sh spawns worker
5. execute.sh claims issue, posts plan
6. Worker waits for thumbs-up approval
7. Worker executes in worktree
8. Worker creates PR via gh CLI
9. aggregate.sh collects status
10. generate-briefing.sh creates daily briefing
11. deliver_to_inbox() delivers to Mission Control

**Evidence:** `.worker/inbox/`, `.worker/briefings/latest.md`, GitHub PR #2

### Flow 2: Worker → Sub-agent → Aggregation

**Status:** COMPLETE

1. Worker detects execution graph in PLAN.md
2. validate_dag() ensures no cycles
3. spawn_wave() launches parallel sub-agents
4. Sub-agents execute with scoped constraints
5. wait_for_subagent() monitors completion
6. aggregate_wave_results() collects outputs
7. create_wave_commit() unifies results

**Evidence:** `.worker/agents/test-parent/constraints.json`, execute.sh lines 36-38

### Flow 3: Trust Violation → Approval → CEO Decision

**Status:** COMPLETE

1. validate_command() detects violation
2. Violation recorded in trust-scores.json
3. Critical violation triggers approval request
4. Message delivered to inbox (tier=immediate)
5. CEO sees in dashboard
6. CEO approves/denies via approval-workflow.sh
7. Transition logged to registry.jsonl
8. Briefing includes blockers section

**Evidence:** `.worker/approvals/registry.jsonl` (5 entries), `.worker/inbox/critical_violation.md`

**Flow Score:** 3/3 complete (100%)
