# Requirements: Manifest Automations AI Agency

**Version:** 1.0 (MVP)
**Created:** 2026-01-26
**Core Value:** Complete loop where CEO dispatches intent, orchestrator routes, Claude executes, results land in GitHub with status reporting back.

---

## v1 Requirements

### Foundation

- [x] **FOUND-01**: Repository configured with git submodules for multi-project structure
- [x] **FOUND-02**: Agent manifest schema defined in YAML format with model, tools, triggers, constraints
- [x] **FOUND-03**: Directory structure established (.claude/commands/, .claude/skills/, .claude/agents/, .planning/, projects/, templates/)
- [x] **FOUND-04**: Dynamic worktree management — auto-create worktrees per task, cleanup based on outcome (success = remove, failure = preserve)

### Orchestration

- [x] **ORCH-01**: Single Gemini orchestrator can dispatch work to Claude workers
- [x] **ORCH-02**: Orchestrator decomposes high-level CEO intent into discrete subtasks
- [x] **ORCH-03**: Cross-surface terminal control — orchestrator invokes `claude-code --prompt --skill --context` via terminal
- [x] **ORCH-04**: Model selection encoded in agent manifests (Flash for fast routing, Pro for complex reasoning, Deep Think for architecture)

### Worker Execution

- [x] **WORK-01**: Claude worker executes commands and skills via GSD framework
- [x] **WORK-02**: Worker reports status and results via gh CLI (issue updates, PR creation)
- [x] **WORK-03**: Worker can spawn sub-agents for parallelization of independent subtasks
- [x] **WORK-04**: Each worker operates in isolated git worktree to prevent conflicts

### GitHub Coordination

- [x] **GH-01**: GitHub issues serve as work items (task assignment, status tracking, context storage)
- [x] **GH-02**: Pull requests represent completed work (code changes linked to issues)
- [x] **GH-03**: GitHub Projects provide kanban-style state visualization
- [x] **GH-04**: GitHub is single source of truth — no proprietary state management, all coordination via gh CLI

### Trust & Guardrails

- [x] **TRUST-01**: Pre-hooks enforce command sanitization (block destructive operations, validate scope)
- [x] **TRUST-02**: Post-hooks validate outputs and log actions for audit trail
- [x] **TRUST-03**: Basic access control — agents have defined scope boundaries per manifest

### Observability

- [x] **OBS-01**: Structured logging (JSON format) for all agent actions and decisions
- [x] **OBS-02**: Error tracking captures agent failures with full context for debugging

### CEO Interface

- [x] **CEO-01**: Status visibility — CEO can see what agents are doing and their results
- [x] **CEO-02**: Decision points — approval gates for high-stakes actions requiring human judgment
- [x] **CEO-03**: Anti-Gravity Mission Control serves as primary inbox interface
- [x] **CEO-04**: Daily briefings aggregate completions, in-progress items, blockers, and escalations
