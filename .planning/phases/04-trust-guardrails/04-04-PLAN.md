Create hooks.sh that orchestrates pre/post hooks around command execution:

**Dependencies (source at top):**
```bash
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
source "$SCRIPT_DIR/validator.sh"
source "$SCRIPT_DIR/audit.sh"
```

**Core functions:**

1. `execute_with_hooks(agent, trust_level, command...)` - Main wrapper
   - Extract command from arguments
   - Call pre_hook to validate
   - If blocked: log, provide feedback, return 1
   - If confirm: call confirm_with_timeout
   - If allowed: execute command
   - Call post_hook to log result
   - Return command exit code

2. `pre_hook(agent, trust_level, command)` - Pre-execution validation
   - Call validate_command from validator.sh
   - Parse result JSON
   - If action=block:
     - Print formatted block message
     - Print alternatives if available
     - Log to audit trail
     - Return 1
   - If action=confirm:
     - Print confirmation prompt with severity and reason
     - Call confirm_with_timeout
     - If timeout or denied: log and return 1
     - If approved: log approval and return 0
   - If action=allow:
     - Log command_allowed
     - Return 0

3. `post_hook(agent, command, exit_code, output)` - Post-execution logging
   - Log command_completed to audit trail
   - Include exit code, output length, duration
   - If exit_code != 0: log as command_failed
   - Apply trust decay on success (clean action)

4. `confirm_with_timeout(timeout_seconds)` - Confirmation gate
   - Print confirmation prompt
   - Use `read -t $timeout` for timeout
   - Accept y/Y as approval
   - Default deny on timeout or invalid input
   - Return 0 for approved, 1 for denied

5. `format_block_message(severity, command, reason, alternatives)` - Format block output
   - Clear visual separator
   - Show severity with emoji/marker
   - Show blocked command
   - Show reason
   - Show alternatives if available
   - Show escalation path if available

6. `format_confirm_message(severity, command, reason, timeout)` - Format confirm prompt
   - Show warning header
   - Show severity and command
   - Show reason for confirmation requirement
   - Show timeout countdown

**GitHub integration (for non-TTY confirmation):**

7. `request_github_approval(issue, command, reason)` - Post approval request
   - Create a comment requesting approval
   - Include command details and reason
   - Provide instructions for approval (thumbs up reaction)
   - Return comment ID for polling

8. `check_github_approval(issue, comment_id)` - Check for approval
   - Query reactions on comment
   - Return true if thumbs up found
   - This allows confirmation when no TTY available

**Implementation notes:**
- TTY detection: `[ -t 0 ]` for interactive terminal
- Non-TTY falls back to GitHub approval workflow
- All audit events use log_audit_event from audit.sh
- Timeout default: 30 seconds (configurable)
- Severity emojis: critical=stop_sign, high=warning, medium=caution, low=info
