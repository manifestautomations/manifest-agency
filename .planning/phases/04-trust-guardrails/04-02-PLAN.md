<task type="auto">
  <name>Task 2: Create audit.sh library with hash chaining</name>
  <files>.claude/skills/worker/lib/audit.sh</files>
  <action>
Create audit.sh following the pattern from logger.sh but with hash chaining:

**Functions to implement:**

1. `init_audit_chain()` - Initialize audit chain
   - Create .worker/audit/ if missing
   - Create chain.json with genesis checksum if not exists
   - Genesis checksum: 64 zeros (SHA-256 null)
   - Track: last_checksum, last_timestamp, entry_count

2. `log_audit_event(event_type, [--arg key value]...)` - Log with hash chain
   - Load previous checksum from chain.json
   - Build event JSON (same pattern as log_event)
   - Include fields: event_type, event_id, timestamp, previous_checksum, data
   - Calculate SHA-256 of entry (before adding checksum field)
   - Add checksum field to entry
   - Append to daily audit file: .worker/audit/YYYY-MM-DD.audit.jsonl
   - Update chain.json with new last_checksum

3. `verify_audit_chain()` - Verify chain integrity
   - Iterate all .audit.jsonl files in chronological order
   - For each entry:
     - Verify previous_checksum matches expected (chain continuity)
     - Recalculate checksum from entry content
     - Verify matches stored checksum (tamper detection)
   - Return success if chain valid, error with details if broken

4. `get_audit_stats()` - Return audit statistics
   - Total entries, entries by type, last violation time

**Implementation notes:**
- Use sha256sum for hashing (standard coreutils)
- Use jq for JSON construction (consistent with logger.sh)
- Daily log files prevent single file growing too large
- chain.json provides quick access to last checksum without parsing all logs
- Files should be append-only (never modify existing entries)

**Entry schema:**
```json
{
  "event_type": "command_allowed|command_blocked|violation_recorded|...",
  "event_id": "audit-{timestamp}-{pid}",
  "timestamp": "ISO8601",
  "previous_checksum": "sha256",
  "data": { ... },
  "checksum": "sha256"
}
```
