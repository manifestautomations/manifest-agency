Create status aggregation helper that queries GitHub for worker state.

Command-line interface:
```bash
./aggregate.sh                        # Default: table format
./aggregate.sh --format oneliner      # Quick summary
./aggregate.sh --format table         # Progress view
./aggregate.sh --format detailed      # Full JSON output
./aggregate.sh --scope active         # Only active workers (default)
./aggregate.sh --scope phase          # All issues in current phase
./aggregate.sh --scope all            # All issues
```

Functions to implement:

1. `aggregate_status()` - Main aggregation function
   - Query GitHub for issues with worker:* labels
   - Group by state (executing, awaiting-approval, complete, failed, partial)
   - Count by category for summary

2. `format_oneliner()` - Quick summary
   - Output: "3 executing, 2 awaiting approval, 1 blocked"
   - Single line for fast status check

3. `format_table()` - Progress view with icons
   - Status icons (text-based for Windows compatibility)
     - Complete: [OK]
     - Executing: [..]
     - Awaiting approval: [??]
     - Failed: [XX]
     - Blocked: [--]
   - Columns: Status | Issue | Title (truncated)
   - Sorted by state priority

4. `format_detailed()` - Full JSON with metadata
   - Include comments, timestamps, assignees
   - For debugging and programmatic access

From RESEARCH.md Pattern 6:
```bash
aggregate_status() {
  local format="${1:-table}"

  case $format in
    oneliner)
      local executing=$(gh issue list --label "worker:executing" --json number --jq 'length')
      # ... count other states
      echo "$executing executing, $awaiting awaiting approval, $blocked blocked"
      ;;
    table)
      # Icon-based table output
      ;;
    detailed)
      gh issue list --label "worker:*" --json number,title,labels,comments,updatedAt
      ;;
  esac
}
```

Use Windows-compatible icons (text-based) instead of Unicode emojis.

Add functions:

2. `report_failure()` - Generate failure report for CEO

   - Error context (from issue comments)
   - Cascade impact (which issues are now blocked)
   - Recovery options (retry, modify, abandon)

3. `label_cascade_blocked()` - Mark affected issues
   - Add "cascade-blocked" label to dependents
   - Post comment explaining the block
   - Reference original failed issue

From RESEARCH.md Pitfall 6:
```bash
detect_cascade() {
  local failed_issue="$1"

  # Find direct dependents
  gh issue list --state open --json number,body --jq '.[] |
    select(.body | contains("Blocked by #'"$failed_issue"'")) |
    .number'
}
```

Failure report format:
```
[XX] Issue #42 failed: "Implement login API"

Error: Test suite failed with 3 errors
  - test_invalid_password: expected 401, got 500
  - test_expired_token: timeout after 30s

Cascade impact:
  - #43: Login UI (blocked by #42)
  - #44: Password reset (blocked by #42)
  - #45: Session management (blocked by #43)

Options:
  1. retry   - Re-run worker for #42
  2. modify  - Update issue scope and retry
  3. abandon - Close #42 and unblock dependents manually
```
