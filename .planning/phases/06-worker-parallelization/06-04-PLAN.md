  <name>Task 1: Create scope validator for write conflict detection</name>
  <files>scripts/worker/lib/scope-validator.sh</files>
  <action>
Create `scripts/worker/lib/scope-validator.sh` with these functions:

1. `detect_write_conflicts()` - Find overlapping write scopes:
   - Input: JSON array of agent constraint files
   - Build map: file -> list of agents writing to it
   - Detect any file with multiple writers
   - Return 0 if no conflicts, 1 if conflicts found
   - Output conflict details on stderr for logging
   - Pattern from RESEARCH.md using associative array

2. `validate_wave_scopes()` - Pre-flight validation before wave dispatch:
   - Input: wave_id, array of task definitions
   - For each task, extract write_scope
   - Call detect_write_conflicts with combined scopes
   - Return early with error if any conflict
   - This MUST be called BEFORE spawning any agents in wave
   - Per RESEARCH.md Pitfall 4: validate BEFORE spawn, not during

3. `get_file_writer()` - Query which agent writes to a file:
   - Input: file_path, wave_agents array
   - Returns agent_id that has file in write_scope
   - Returns empty if no agent writes to file
   - Used for debugging conflicts

4. `expand_glob_scope()` - Handle glob patterns in write scope:
   - Input: scope array (may contain globs like "src/**/*.ts")
   - Output: expanded file list
   - Required for accurate conflict detection

Header should include:
- Shebang: #!/usr/bin/env bash
- set -euo pipefail
- Source subagent-scope.sh for constraint access

IMPORTANT: Per CONTEXT.md - "Write scopes must not overlap between parallel sub-agents. Worker validates before spawning wave."

<task type="auto">
  <name>Task 2: Create sub-agent spawner with PID tracking</name>
  <files>scripts/worker/spawn-subagent.sh</files>
  <action>
Create `scripts/worker/spawn-subagent.sh` following Phase 5 dispatch.sh patterns:

1. Core infrastructure:
   - Source all lib scripts: graph-parser.sh, subagent-scope.sh, timeout-manager.sh, scope-validator.sh
   - Associative array: `declare -A subagent_pids=()` for PID tracking
   - Arrays: completed_agents=(), failed_agents=()
   - MAX_CONCURRENT setting (default 3)

2. `spawn_subagent()` - Spawn single sub-agent:
   - Inputs: parent_id, task_json, background (bool)
   - Generate agent_id via generate_agent_id
   - Check nesting limit before proceeding
   - Derive constraints from parent (fail if escalation)
   - Create context bundle
   - Register in agent registry
   - Execute command with timeout
   - If background: track PID in subagent_pids[$agent_id]
   - IMPORTANT: Capture PID immediately after & (per Pitfall 2)

3. `spawn_wave()` - Spawn all agents in a wave:
   - Input: wave_tasks (JSON array), parent_id
   - FIRST: Call validate_wave_scopes (pre-flight)
   - Then: spawn_subagent for each task with concurrency limit
   - Use wait -n pattern from dispatch.sh for job control
   - Track completion/failure in arrays

4. `wait_for_subagent()` - Wait for any sub-agent to complete:
   - Pattern directly from dispatch.sh wait_for_worker
   - Check which PIDs completed using kill -0
   - Capture exit codes via wait $pid
   - Update completed_agents/failed_agents
   - Remove from subagent_pids tracking

5. `get_subagent_status()` - Query agent status:
   - Input: agent_id
   - Check PID if running, or result arrays
   - Return: running/complete/failed/unknown

CLI interface for direct invocation:
- --spawn: spawn single agent
- --wave: spawn wave of agents
- --status: show running agents
