  <action>
Create scripts/portfolio/portfolio-briefing.sh that generates a unified briefing across all workspaces.

Script structure:
1. Standard header with usage documentation
2. SCRIPT_DIR and REPO_ROOT resolution
3. Source portfolio-status.sh
4. Output paths: BRIEFINGS_DIR="$REPO_ROOT/.worker/briefings", OUTPUT default="$BRIEFINGS_DIR/portfolio-latest.md"

Cross-platform date functions (copy from generate-briefing.sh):
- get_timestamp() - ISO 8601 format
- get_date() - YYYY-MM-DD format
- get_epoch() - epoch seconds

Functions to implement:

**collect_workspace_blockers():**
- Parameter: workspace_path, workspace_name
- Check "$workspace_path/.worker/approvals/pending" for approval files
- For each pending approval:
  - Extract type, agent_id, timeout_at, context from JSON
  - Format as: "- **[workspace_name] type** for agent - context"
- Return formatted blocker lines or empty string

**check_workspace_has_updates():**
- Parameter: workspace_path
- Look for activity indicators:
  - Recent commits (git log --since="24 hours ago" | wc -l > 0)
  - New SUMMARY.md files (find -newer timestamp)
  - Pending inbox items
- Return "true" if any updates, "false" otherwise

**generate_blockers_section():**
- Iterate all workspaces (from collect_portfolio_status)
- Collect blockers from each workspace
- Also check for RED health status as blocker
- If any blockers: return section with all blockers
- Else: return empty string (section collapses)
- Format:
  ```
  ## Blockers

  - **[ProjectA] trust_promotion** for agent-1 - Requesting level 3
  - **[ProjectB]** RED health - Trust ledger missing
  ```

**generate_executive_summary_section():**
- Iterate all workspaces
- Count: projects_with_updates, projects_no_updates
- Identify projects needing attention (RED health or pending > 0)
- Format:
  ```
  ## Executive Summary

  - Projects with updates: N
  - Projects with no updates: M
  - Projects needing attention: K
  ```

**generate_per_project_sections():**
- Only include projects that have updates
- For each project with updates:
  - Get workspace path
  - Check for completions in dispatch log
  - Check for new summaries
  - Check pending items
  - Format:
    ```
    ### ProjectName

    - Completions: N
    - Pending: M items
    - Health: GREEN
    ```
- Projects without updates are NOT shown (mentioned in summary count only)

**generate_portfolio_briefing():**
- Parameter: output_file (optional, defaults to portfolio-latest.md)
- Build briefing:
  1. Header: `# Portfolio Briefing - YYYY-MM-DD`
  2. generate_blockers_section (collapses if empty)
  3. generate_executive_summary_section
  4. generate_per_project_sections
  5. Footer: `---\n_Generated: timestamp_`
- Write to output file
- Archive previous briefing to history (copy pattern from generate-briefing.sh)

CLI interface:
- No args: generate to default output
- First arg: custom output path
- `--date YYYY-MM-DD`: generate for specific date (for header)
- `help`: show usage

Direct execution block with set -euo pipefail inside the if block.

Export functions: generate_portfolio_briefing

Integration with inbox:
- After generating briefing, check for inbox-integration.sh
- If available, deliver briefing notification with tier="briefing"
- Use duplicate check to prevent double-delivery same day
